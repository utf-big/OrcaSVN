## 开始使用

### 准备软件和 SVN

OrcaSVN 是 SVN 桌面客户端，需要本机已安装 SVN 命令行工具。软件本身不代替 SVN 服务端，也不创建远端仓库。

1. 从项目的 [发行下载页](https://github.com/wustites/OrcaSVN/releases) 选择适合操作系统的安装包。
2. 安装 SVN 命令行工具。在终端运行 `svn --version --quiet`，应输出版本号。
3. 启动 OrcaSVN。若找不到 SVN，进入“设置”，在“SVN 可执行文件”中填写实际程序路径，例如 `C:\Tools\Subversion\bin\svn.exe`。

路径应指向程序文件，而不是安装目录。留空时使用系统环境中的 `svn`。连接受限仓库前，准备好仓库地址及团队要求的访问权限；认证失败时按 SVN 错误信息检查凭据或联系仓库管理员。当前没有独立的账号管理页面。

### 已经有本地项目

点击“打开工作区”，选择已有 SVN 工作副本目录。通常这是含有 `.svn` 元数据的项目根目录，例如 `D:\projects\eagle`。普通文件夹不会因为被打开就自动成为 SVN 工作副本。

### 第一次取得项目

进入“检出”页面：

| 字段 | 如何填写 |
| --- | --- |
| 仓库 URL | 团队提供的地址，例如 `https://svn.example.com/repo/trunk` |
| 目标目录 | 本地保存项目的目录；建议使用专用的新目录 |
| 版本 | 留空取得最新版本，或输入需要检出的历史版本号 |

点击“开始检出”后，SVN 一在目标目录里建好 `.svn`（通常不到 1 秒，早于文件传输），该目录就成为**当前工作区**（左侧和最近工作区里都能看到），同时页面下方显示检出进度：

| 区域 | 内容 |
| --- | --- |
| 状态标签 | 检出中、检出完成、检出失败、已取消 |
| 统计 | 新增、更新、删除、冲突数量，已处理条目数和耗时 |
| 明细列表 | SVN 输出逐行显示，保留最近 300 条（完整计数不受影响） |
| 失败处理 | 显示错误原因和“重试（继续检出）”按钮 |

进度与明细只在当前页面显示：切换到其他页面即消失，也不会写入本地记录。

切换工作区的时机以“目录已成为工作副本”为准，而不是按下按钮的瞬间：否则日志页、更新页会先对还不是工作副本的目录发起 `svn log`，得到 `svn: E155007: ... is not a working copy`。这段等待通常只有几百毫秒。

检出不会因为切换页面而停止，它会在后台继续执行；但离开检出页后就看不到进度，也无法在那里取消。需要中断时请在检出页点“取消”。

取消（或失败）之后，已取到的内容会保留在目标目录，可以到“更新”页面顶部继续（这里的续传只针对工作副本本身，因此不受目标目录 URL 写法差异影响，例如含中文的地址）：

| 位置 | 行为 |
| --- | --- |
| 更新页“继续上次检出” | 显示上次检出的目录与状态（已取消／失败／进行中） |
| 继续检出 | 从当前进度继续，不会重新下载已有内容；也会把抢救流程留下的浅深度工作副本补到完整深度 |
| 放弃 | 清除这条待续记录，目标目录保持不变 |

检出进行中时，工作区的定时状态核对会暂停，避免和正在写入的 SVN 操作互相干扰；因此工作区文件列表要等检出结束或手动刷新后才完整。

大仓库检出时可能遇到“响应被截断”类错误（`svn: E175009` / `svn: E130003`：The XML response contains invalid XML）。原因是服务器把文件内容内联进一次 update-report，响应体积接近整个仓库，容易被代理或超时截断；不是仓库数据损坏。

应用的处理顺序：

| 尝试 | 传输方式 |
| --- | --- |
| 第 1 次 | 默认（bulk update，速度最快） |
| 第 2 次 | `http-bulk-updates=no`：逐个文件单独请求，报告体积大幅下降 |
| 第 3 次 | 在第 2 次基础上再关闭 HTTP 压缩、把 HTTP 超时放宽到 900 秒 |

每次重试前都会执行 `svn cleanup`，并且**已检出的内容保留**，所以重试是从当前进度继续，不会从头再来。一旦某个仓库出现过这种截断，本次运行内再次检出它会直接使用逐文件方式。

若三次仍失败，说明服务器或代理的限制更严格，请让仓库管理员把 Apache 的 `SVNAllowBulkUpdates` 设为 `off`，或放宽代理的超时与响应大小限制。

检出是从仓库取得文件；打开工作区是使用已经检出的本地文件。

### 第一次修改并提交

1. 打开工作区，在“更新”页面检查并取得远端修改。
2. 使用编辑器修改项目文件。
3. 回到 OrcaSVN，点击“刷新”，在工作区选择文件查看差异。
4. 进入“提交”，核对勾选范围，填写提交说明。
5. 点击提交，成功后回到工作区确认剩余修改。

例如：只修复 `trunk/app.ini` 中的配置时，提交页只勾选这个文件，说明写为“修正默认连接超时时间”，其余尚未完成的修改留在本地。

## 管理工作区

通过顶部工作区切换器使用最近打开的路径。切换前核对当前目录，尤其是同一仓库的多个工作副本。工作副本之间的本地修改不会自动同步，只有提交到仓库后的内容才能通过更新取得。

“打开方式”提供资源管理器、VS Code 和终端入口。相应外部程序需在本机可用。工作区文件的右键菜单可在资源管理器中定位文件、复制相对路径或绝对路径。

### 刷新与缓存提示

“刷新”核对本地工作副本状态，不会把远端修改更新到本地，也不会提交修改。

再次打开工作区时，软件可能先显示之前保存的文件列表，再核对实际状态。出现缓存或未验证提示时，列表不一定反映当前磁盘内容；提交、创建贮藏以及工作区还原/删除暂时不可用。等待验证完成，或点击刷新。验证失败时应处理错误，不能把旧列表当作最新状态。

也可以打开工作副本中的子目录；刷新会同时核对所属工作副本的 SVN 管理状态。升级到 0.6.3 后，原生状态缓存会重新建立一次，首次打开可能需要完整扫描。

工作区加载时间取决于文件数量、磁盘、杀毒软件及文件系统状态等。提交历史条数与本地状态检查不是同一件事；仓库历史很多，不一定意味着本地加载同样慢。

## 查看与处理文件状态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 修改 | 已纳入版本控制的文件存在本地修改 | 审阅差异后提交、贮藏或还原 |
| 新增 | 已安排加入版本控制，但尚未提交 | 确认文件应进入仓库后提交 |
| 删除 | 已安排从版本控制中删除，尚未提交 | 核对删除范围后提交，或还原 |
| 替换 | 原条目被新的条目替换 | 检查完整操作范围 |
| 未跟踪 | 文件存在，但尚未纳入版本控制 | 在提交页加入版本控制，或保留在本地 |
| 冲突 | 修改不能自动合并 | 编辑文件解决冲突，再点击行内“标记为已解决”选择处理策略 |
| 缺失 | 受版本控制的文件在磁盘上不存在 | 用“还原”恢复文件，或点击行内“安排删除”标记版本控制删除 |
| 文件名编码不一致 | 文件在磁盘上存在，但文件名的 Unicode 形式与版本库不同（NFC/NFD），SVN 因此报为缺失 | 本地名字漂移时点“修复文件名”；仓库里存在两种拼写时点“删除重复条目” |
| 阻塞 | 文件系统中的条目妨碍 SVN 操作 | 阅读 SVN 错误并检查路径、文件类型与工作副本状态 |

顶部分类帮助缩小列表；“变更”包含修改、新增、删除和替换，“未跟踪”独立显示。工作区列表不是所有项目文件的文件浏览器，正常且无修改的文件可能不在其中。

### 还原已纳入版本控制的文件

点击文件行的还原按钮，阅读警告及完整路径，再确认“还原”。还原丢弃该目标的本地修改，不会撤销已经提交到仓库的历史。需要保留修改时，先创建适用的贮藏或另外备份文件。

### 标记冲突已解决

冲突文件会显示为“冲突”，并且不会出现在提交页。处理步骤：

1. 在工作区选中该文件，右侧查看差异，必要时直接编辑文件。
2. 点击文件行的“标记为已解决”，选择策略：

| 策略 | 结果 |
| --- | --- |
| 保留当前内容 | 只清除冲突状态，文件内容保持不变；文件中的冲突标记需要自己删除 |
| 采用本地版本 | 丢弃仓库带来的修改，保留本地内容 |
| 采用仓库版本 | 丢弃本地修改，采用仓库内容 |

3. 刷新后文件应回到“修改”状态，可以正常提交。

标记解决不是提交：它只改变工作副本的冲突状态。SVN 仍可能保留 `.mine`、`.r1`、`.r2` 等临时文件，确认无用后可自行删除。

### 检出时提示服务器数据读取失败

出现下面这类错误时，问题在**服务器**，不在本机：

```text
svn: E000005: Can't read file '/data/svn/repos/<repo>/db/revs/3/3434': Input/output error
```

消息里带的是服务器上的仓库路径，说明服务器读不出某个版本文件的数据块（磁盘坏道、文件系统损坏或存储掉线）。客户端任何设置都无法绕过；同一次故障在旧版本里也可能表现为“响应被截断”（`E175009`/`E130003`），因为服务器在传输中途异常退出。

处理建议：

| 角色 | 动作 |
| --- | --- |
| 使用者 | 点“跳过失败项继续检出”，先把其余文件取下来照常工作；面板会列出未能完整检出的目录 |
| 仓库管理员 | 在服务器上执行 `svnadmin verify /data/svn/repos/<repo>` 定位受影响的版本；用 `dmesg`／SMART 检查磁盘；必要时从备份恢复受影响的 rev 文件 |
| 修复后 | 回到本应用对同一目录重新“开始检出”或“更新”，缺失部分会自动补齐 |

“跳过失败项继续检出”的做法是：先只取目录骨架，再逐个目录取全；某个目录失败就保留已下载内容并继续向内拆分，因此只有真正读不到的文件会缺失。

### 文件名编码不一致（macOS 常见）

同一个日文或中文文件名有两种 Unicode 写法：预组合（NFC，如 `ポ`）和组合字符（NFD，如 `ホ` + 浊点）。两者字节不同，但 macOS 把它们视为同一个名字。SVN 用字节比对，于是出现“文件明明在，却报缺失”。有两种成因，处理方式不同：

**一、本地名字漂移（可本地修复）**

版本库里只有一种拼写，磁盘上的名字被其他工具改成了另一种写法。此时：

1. 提示条说明检测到 N 个文件名与版本库写法不一致，文件并未丢失。
2. 点击提示条上的“全部修复”或行内“修复文件名”。
3. 该操作只按版本库写法重命名磁盘文件，不改内容，也不提交。
4. 修复后刷新，条目消失，工作副本回到干净状态。

**二、仓库里存在两种拼写（必须改仓库）**

版本库里同一个文件同时存在两种拼写的两条记录（常见于先用 macOS 提交、后来又在 Windows 或工具里重新提交了一次）。macOS 只能落地其中一个，因此另一个**每次检出都会显示缺失**，本地改名只会让两者互换，永远修不好。

此时提示条会说明“仓库中有 N 个文件名存在两种 Unicode 拼写（内容相同）”：

1. 点击“全部删除重复”或行内“删除重复条目”。
2. 该操作只把多余的那条记录标记为删除，**磁盘文件保留**。
3. 到“提交”页确认并提交这次删除。
4. 之后再检出（包括同事的机器）不会再有虚假缺失，也不需要任何提示。

判断依据：行内按钮是“删除重复条目”表示仓库有重复；是“修复文件名”表示只是本地漂移。不要对这类条目使用“还原”：它会按另一条记录重新写出一份文件，让问题在两条记录之间来回摇摆。

### 关闭窗口与退出程序（macOS）

| 快捷键 / 操作 | 行为 |
| --- | --- |
| ⌘W 或「窗口 > 关闭窗口」 | 只关闭窗口（隐藏），应用继续在 Dock 中驻留，正在进行的检出／更新不会中断 |
| 点击 Dock 图标 | 窗口重新显示（原来的工作区与页面状态还在） |
| ⌘Q 或「OrcaSVN > 退出」 | 退出整个程序 |

这样做是为了避免“关掉窗口就把整个程序和正在跑的任务一起结束”。需要真正退出时用 ⌘Q。

### 打开远程仓库地址

顶部工具栏“打开方式”右侧有“远程仓库”按钮（工作区页面同样可见）：点击后用系统默认浏览器打开当前工作副本的仓库地址。地址取自 `svn info` 的 URL，切换工作区后会自动更新；尚未读取到地址时按钮不可用（悬停会提示原因）。

### 工作副本被锁定

更新或提交时出现下面的提示，说明上一次 SVN 操作被中断（例如取消了检出、强制退出应用），工作副本留下了锁：

```text
svn: E155004: Run 'svn cleanup' to remove locks
svn: E155004: Working copy '...' locked.
```

处理方式：

| 位置 | 操作 |
| --- | --- |
| 自动 | 下一次“更新”或“继续检出”检测到锁时会自动执行 `svn cleanup` 后重试，明细里会出现“工作副本被锁定：自动执行 svn cleanup 后重试” |
| 更新页 | 顶部工具栏的“清理”按钮 |
| 检出页 | 失败后操作区里的“清理”按钮 |
| 工作区页 | 左侧栏底部的“清理” |

清理只处理锁和未完成的操作队列，不会修改文件内容。检出正在进行时，“更新”按钮会暂时不可用——此时工作副本由检出的进程占用，等它结束或取消后再更新。

### 切换仓库地址与合并

工作区侧栏的两个入口对应 `svn switch` 和 `svn merge`：

| 操作 | 填写的字段 | 结果 |
| --- | --- | --- |
| 切换仓库地址 | 目标 URL | 工作副本改为跟踪目标 URL，未提交的修改保留，可能需要解决冲突 |
| 合并 | 源 URL、起始版本、结束版本 | 把该版本范围合并进当前工作副本，结果留在本地待提交 |

两者都只修改工作副本，不会自动提交。合并后请先在工作区核对文件状态、处理冲突，再进入提交页。

### 安排版本控制删除

受版本控制的文件在磁盘上被直接删除后，状态显示为“缺失”。此时有两个选择：

- **还原**：把文件从 SVN 基准恢复到磁盘。
- **安排删除**：把删除动作安排进下一次提交。文件已不在磁盘，只有提交后才会从仓库移除。

“安排删除”与“删除未跟踪文件”不同：后者会物理删除本地内容，无法通过 SVN 恢复。

### 删除未跟踪文件

未跟踪文件行的删除按钮会永久删除本地目标；删除目录也会删除其中内容，不进入回收站。它与“把受控文件的删除提交到仓库”不同。确认框中核对路径，点击“取消”或关闭即可退出；点击遮罩不会关闭确认框。

## 提交修改

提交把勾选的本地变更发送到仓库，成功后生成新的仓库版本。没有勾选的修改继续留在工作副本。

### 选择范围

1. 进入“提交”，查看当前工作区路径与文件树。
2. 勾选需要提交的文件；勾选目录会联动其下可提交子项，也可逐项取消。
3. 使用搜索和分类过滤列表，检查顶部已选数量。
4. 审阅差异，返回提交页后核对勾选和说明。
5. 输入说明并提交。

搜索或筛选隐藏的已选文件仍计入提交，不会因为当前看不见就自动取消。提交前以已选总数和实际范围为准，避免带入无关修改。

### 新文件和新目录

未跟踪文件需要先加入版本控制。未跟踪目录通过“加入版本控制并预览”展开后，检查其内容再提交。加入版本控制只是安排新增，不等于已经提交到远端；若之后取消提交，仍需检查工作区中的新增状态。

### 目录操作的限制

删除或替换目录时，必须完整选择所需子项。复制或移动目录暂不支持部分提交；遇到相关提示，请用其他 SVN 客户端处理完整操作。不要为了通过提交检查而忽略提示中的目录关系。

### 提交说明

说明应回答“改了什么、为什么改”。例如：

```text
修复配置文件中默认超时时间错误

将默认值调整为团队约定值，避免首次连接过早超时。
```

页面提供最近提交说明，复用前应修改为适合本次内容的文字。提交失败时保留错误信息，并刷新确认当前状态；不要直接假定已经成功或完全没有产生变化。

## 获取远端更新

更新开始后可以切换到其他页面；操作完成时仍会刷新工作区的本地版本和变更列表。离开更新页后暂停自动远端查询，返回时恢复。

“更新”页面显示本地版本、远端版本、列出的远端提交以及本地更改。

1. 点击“检查”，审阅远端提交和本地更改。
2. 需要暂时保存本地工作时，先备份或贮藏支持的修改。
3. 点击“更新”，等待操作结束。
4. 回到工作区刷新，检查冲突和剩余修改。

“远端提交”数量是页面当前列出的记录数量，不应当作整个仓库历史总数。更新可能合并本地修改，也可能产生冲突；它不会自动提交你的本地工作。

## 查看代码差异

工作区选择文件可直接预览差异，也可进入“对比”页面，选择当前工作区内的文件。

| 模式 | 比较内容 |
| --- | --- |
| 工作副本 vs 基准 | 本地内容与 SVN 工作副本基准的差异 |
| 版本间差异 | 同一目标在旧版本、新版本之间的差异；两个版本号都要填写 |
| 提交 rN | 从日志详情进入，查看该次提交涉及的变化 |

新增行有 `+`，删除行有 `-`，上下文行帮助定位修改。行内查找区分大小写，使用上一个/下一个匹配定位；复制按钮复制完整 Diff。没有差异与加载失败是不同状态，应结合页面提示判断。

从提交页审阅多个文件时，可用“上一个”“下一个”切换，再点击“返回提交”。二进制内容不一定能显示逐行文本差异。

## 查询提交历史

进入“日志”，默认每页显示 20 条提交。使用上一页、下一页浏览；作者、关键词、日期范围可组合筛选，填写后点击“查询”，点击“重置”清除条件。

表格显示版本、作者、日期、提交信息等。长作者名和提交信息省略显示，悬停查看全文。点击记录打开详情，查看完整说明和涉及路径，再选择相关文件查看提交差异。

筛选结果为空时，先检查日期范围、作者和关键词，再重置条件。日志显示的是已提交历史，尚未提交的本地修改应在工作区查看。

## 暂时保存修改：贮藏

贮藏用于中断当前工作后再恢复，例如临时处理紧急任务。记录保存在本机应用数据目录下的独立文件中，按工作区路径区分；它不是仓库提交，也不是团队共享备份，其他电脑看不到，清除应用数据同样会丢失。

### 创建

1. 打开“贮藏”，点击“创建贮藏”。
2. 查看文本差异，按文件或分块勾选要保存的修改。
3. 按整文件选择需要保存的未跟踪文件或目录。
4. 输入容易辨识的名称。
5. 点击“保存并从工作副本移除”。

选中的修改保存后从工作副本移除，未选中的修改留在原处。未跟踪文件恢复后仍保持未跟踪状态。受控文件的冲突、仅属性修改及非文本变更暂不支持按此方式贮藏；以实际可选择内容和提示为准。

### 恢复与管理

| 操作 | 结果 |
| --- | --- |
| 应用 | 将内容恢复到原工作区，保留贮藏记录 |
| 弹出并删除 | 应用成功后删除贮藏记录 |
| 删除 | 只删除贮藏记录，不修改当前工作副本 |
| 复制 patch / 导出 patch 文件 | 复制或导出文本补丁部分 |

patch 导出不包含贮藏中另存的未跟踪文件内容；仅有未跟踪文件时可能没有可导出的 patch。需要迁移或备份这些文件时，应另行保存完整文件。

若提示“贮藏已保存，但未能从工作副本移除改动”，记录已保留，先刷新检查实际残留。应用失败时也应检查工作区，不要连续重复应用。清除应用数据目录会删除贮藏记录；重要工作应提交或做独立备份。旧版本保存在浏览器本地存储中的贮藏会在首次打开工作区时自动导入。

## 逐行追溯

在“追溯”页面选择或输入文件，点击“加载”。表格显示行号、最后修改版本、作者和内容，用于定位某一行的历史来源，再结合日志理解修改原因。

追溯反映版本控制历史，不等同于当前尚未提交修改的作者归属。查看本地修改请使用工作区和差异页面。

## 设置与显示

| 设置 | 说明 |
| --- | --- |
| 语言 | 简体中文、繁体中文、英语、日语、韩语；顶部也有语言入口 |
| 主题 | 浅色、深色、自动；自动跟随系统外观 |
| SVN 可执行文件 | 留空使用系统 `svn`，或填写实际程序路径 |
| 默认编码 | UTF-8、GBK、GB2312；用于相关内容解码，不会自动改写项目文件编码 |
| 忽略文件（.gitignore） | 启用后过滤匹配项；默认关闭 |
| 自动更新检查 | 已关闭：本版本为二次开发构建，不检查上游更新 |

`.gitignore` 过滤是界面过滤，不会自动设置 SVN 的忽略属性，也不会把受控文件移出仓库。找不到预期文件时，可关闭过滤并刷新核对。

设置页底部的“关于”区注明：本应用基于开源项目 OrcaSVN 二次开发，并给出上游项目地址 <https://github.com/wustites/OrcaSVN>。自动更新检查在该构建中保持关闭，避免把用户引向上游项目的发布物；代码保留在源码中，如需恢复可打开对应开关。

系统开启减少动态效果时，界面会减少动画，加载文字仍然显示。工作区文件按钮可通过 Tab 获得焦点，用方向键、Home、End 移动；Enter 激活当前按钮。软件没有在本手册中承诺额外的全局快捷键。

## 常见问题

| 问题 | 建议处理 |
| --- | --- |
| 找不到 SVN | 在终端验证 `svn`，检查设置中的程序路径；环境变更后重新启动软件 |
| 目录不是工作副本 | 选择正确的 `.svn` 工作副本根目录，或先检出项目 |
| 提交、贮藏或还原按钮不可用 | 检查缓存验证提示、是否已有操作进行、是否选择了可操作内容 |
| 新文件不在变更分类中 | 查看未跟踪分类；需要提交时在提交页加入版本控制 |
| 列表缺少文件 | 检查状态筛选及 `.gitignore` 过滤，刷新核对；正常文件可能不列出 |
| 更新后出现冲突 | 审阅文件、解决冲突并用适合的 SVN 工具标记解决，再刷新 |
| 工作副本被锁定 | 若没有其他 SVN 操作正在进行，可使用工作区的 Cleanup 入口；持续失败时按 SVN 错误处理 |
| 登录、证书或网络错误 | 核对地址、访问权限、网络及团队的证书配置；保留 SVN 原始错误 |
| 贮藏看不见 | 确认回到创建时的工作区路径；记录不会自动跟随移动后的路径 |
| 乱码 | 检查文件实际编码及默认编码；不要用还原来试图修复显示乱码 |
| 删除或还原后想找回 | 未提交修改可能无法通过 SVN 恢复；检查独立备份或编辑器历史 |

反馈问题时提供：软件版本、操作系统、具体步骤、预期与实际结果、完整错误文字；必要时附截图。对外提交前移除密码、令牌以及不适合公开的仓库地址和文件内容。可通过项目 [问题反馈页](https://github.com/wustites/OrcaSVN/issues) 报告。

## 功能边界

当前主要界面入口涵盖检出、状态查看、部分提交、更新、差异、日志、贮藏、追溯和设置。冲突文件可以在工作区标记为已解决，本地缺失的受控文件可以安排版本控制删除。工作区侧栏还提供“切换仓库地址”（Switch）和“合并”（Merge）；合并结果只留在工作副本，需要核对后提交。

SVN 的基准、本地修改和仓库历史是不同层次：刷新核对本地状态，更新取得远端内容，提交发送本地变更，还原丢弃本地修改，贮藏在本机暂存工作。选择操作前先确认你要改变哪一层。

只需要入门步骤时，参阅[快速使用](../QUICKSTART.md)。
